# 脱敏及发布检查

## 本副本做了什么

- 单独复制可运行源码和必要依赖清单，不含旧Git历史、实际环境配置、数据库、上传文件、截图、日志、缓存、浏览器会话和部署备份。
- 商品标题/名称、货号、展示ID全部重新生成，不是原始值打星或可逆替换；60张图片为独立编写的本地SVG几何示意图，不沿用真实图片链接。
- 五店、企业、运营人员、日期、销量、广告和利润全是虚构示例；正式业务数据库从空库开始。
- 清理默认来源地址、真实租户/表格/企业/店铺标识和共享管理员密码。外部连接默认未配置、禁用，需要使用者自己的授权。
- 新增每份安装独立生成的签名/加密/管理员/数据库凭据，保存在被Git忽略的本地`.env`，不在仓库中提供可用密钥。
- 重新编写启动和MCP文档，没有复制线上服务器操作记录、历史对话或实际配置截图。
- 不包含任何第三方网页端账号密码登录或非公开接口调用。经营数据只通过你自己配置的 MCP，或你从自有系统导出的本地文件进入；没有内置小时级数据来源，小时趋势在接入前显示“不可用”。
- 测试夹具里的商品与类目使用和演示目录一致的中性品类示例。

公开的技术框架、依赖包名、协议工具名、第三方SDK/API标识，以及用户显式选择后才使用的公开技术厂商模型地址，不属于店铺商品品牌数据；保留它们用于兼容和说明。不包含实际商品商标或原店铺归属信息。

## 发布之前

1. 发布副本放在任何私有项目目录之外，单独初始化 Git；不要复制原项目的 `.git`，也不要在上级私有目录执行 `git add`。
2. 不要在发布副本里运行 `scripts/dev.py full` 后直接压缩目录：它会生成含随机密钥的 `.env`、数据库和依赖目录。发布包只从 Git 提交生成（见第 6 步）。
3. 在仓库根目录运行隐私扫描和扫描器自测：

   ```bash
   python3 tests/privacy_audit.py --denylist /仓库之外的路径/private-terms.txt
   PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py'
   ```

   在 Git 仓库里，扫描只检查 Git 会发布的文件（已跟踪文件，以及未被忽略的新文件）。私有词表每行写一个你的真实品牌、店铺、企业、人员、域名或服务器地址；它必须放在仓库之外（放在仓库内会被拒绝运行）。扫描只输出文件位置和类别，从不输出命中的内容。
4. 扫描“0 findings”只是辅助证据，不是脱敏证明：仍要人工检查商品 JSON、所有图片和新增文档。可在本机离线再运行一个成熟的密钥扫描器作为第二道防线；不要把源码上传到在线扫描网站。
5. 执行前端构建、测试及后端回归，记录结果和未验证环境。依赖漏洞和许可证应在发布/生产使用前另行检查。
6. 用自己的身份提交（建议用 GitHub 提供的 noreply 邮箱，避免公开私人邮箱），再从提交生成发布包，不直接压缩工作目录：

   ```bash
   git archive --format=zip --prefix=data-warehouse/ -o ../data-warehouse.zip HEAD
   ```

7. 本项目已选择根目录的MIT `LICENSE`；确认代码、文案和素材的授权，保留版权及许可声明，第三方依赖许可条件仍须分别遵守。许可说明见`LICENSE-STATUS.md`。
8. 用GitHub权限/OAuth/SSH授权发布，不在聊天、issue或仓库里提供GitHub密码或访问Token。

## 使用者须持续保护本地数据

连接自己的MCP后，数据库、凭据、业务数据和下载图片成为私有内容。它们不能因“开源模板”而一并公开。新的导入样本、测试夹具、报错截图、日志、导出CSV及AGENTS上下文同样要检查。

开源模板不会连接原系统，亦不附带任何线上服务器部署凭据。需要生产部署时，应自行配置TLS、最小权限、防火墙、备份、独立密钥和依赖更新策略，不直接采用本地DEBUG运行方式。
